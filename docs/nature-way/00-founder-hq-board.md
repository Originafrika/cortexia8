## Revue hebdomadaire

La revue doit confirmer que le milestone actif n’a pas dérivé vers “tous les modèles” ou “tous les flows”. Elle doit vérifier la qualité des preuves plutôt que le volume de pages livrées, rapprocher le paiement fournisseur de la ligne `credits_ledger`, inspecter les états d’échec et de récupération, puis enregistrer une décision **keep / change / pause / stop** avec un propriétaire et une condition de réexamen.

La décision de cette revue est : **change** le milestone vers la Developer Platform, **keep** le compte, le ledger, Mobile Money et la génération vérifiée, **prioriser** les clés API, le playground et l’accès à toutes les catégories vérifiées, puis **pause** le canvas grand public, les agents autonomes non bornés, l’expansion Canva et le catalogue non réconcilié jusqu’à preuve de l’API.

## Prochaine action minimale

Conserver les migrations versionnées comme seule voie opérateur et garder les gates locaux verts. Prochaine action : valider le build, déployer la tranche Developer Platform, vérifier une session développeur autorisée, créer une clé nommée, confirmer le minimum de recharge à 1 USD, tester un modèle vérifié dans le playground et vérifier l’appel API sans exécuter d’action fournisseur non confirmée.
