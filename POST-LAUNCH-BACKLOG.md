# Cortexia8 Post-Launch Cleanup Backlog

## Executive assessment

The production release gate is green for installation, unit tests, strict TypeScript, production build, dependency audit, and peer dependencies. The remaining ESLint backlog is substantial but is dominated by formatting drift rather than runtime correctness. A repository-wide ESLint run over `src`, `server`, `vite.config.ts`, and `eslint.config.js` reported **722 problems: 709 errors and 13 warnings**. Of those, **664 errors and 0 warnings are automatically fixable** with ESLint’s `--fix` option, and the largest class is `prettier/prettier`.

The backlog should not be treated as one undifferentiated cleanup. Formatting can be automated in a controlled branch, while type-safety, authentication, payment, webhook, and route-safety findings require focused code review and tests.

## Recommended execution sequence

The first post-launch maintenance window should remove or gate `/run-migration`, correct the runbook variables, and add staging-backed payment reconciliation checks. The second should be a mechanical formatting pass followed by a clean lint gate. The third should address explicit-any and hook warnings in authentication, canvas, and provider-boundary code. Package upgrades and copy/i18n work should follow only after the first two windows are stable.

## Release-gate policy after launch

A pull request that touches authentication, credits, payment orders, provider webhooks, storage, or model pricing should pass frozen installation, unit tests, strict TypeScript, production build, dependency audit, changed-file ESLint, and a staging smoke test. Formatting-only changes may be merged separately, but they must not be used to conceal functional changes.
