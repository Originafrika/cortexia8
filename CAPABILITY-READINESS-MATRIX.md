# Cortexia Capability Readiness Matrix

**Baseline branch:** `chore/post-launch-eslint-cleanup`

**Purpose:** Track whether each promised Cortexia capability is ready for a normal authenticated user. Administrator access is not treated as proof of product readiness. Stripe-backed card, crypto, and Alipay routing is treated as an intentional payment decision; each method still requires provider/account verification before being marked live.

## Readiness states

**Ready** means a standard authenticated staging user can complete the journey and the evidence includes the provider task or payment reference, expected quote, ledger record, output/history record, and no unreconciled errors. **Beta** means the journey is usable but has a documented provider or product limitation and is explicitly labeled. **Blocked** means the user-facing route is unavailable, the provider contract is unverified, or a financial/ownership invariant is incomplete. **Disabled** means the feature is intentionally paused by a server-side readiness control, with an explicit user-facing explanation.

## Phase 1 decisions

The permanent interpretation for payments is: Mobile Money uses FedaPay; card, crypto, and Alipay selections intentionally use Stripe. The implementation must verify Stripe support rather than silently relabel or substitute another rail. The permanent interpretation for other unavailable capabilities is: they are unfinished or broken until their normal-user journey passes; administrator visibility is not a readiness signal.
